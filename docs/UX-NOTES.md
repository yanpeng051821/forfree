# 选品体验取舍

## 2026-10-21 · 最终商户入口与自适应表格

新品录入必须有明确商户上下文。全部商家、未填写商家和没有看货商户时，主操作是选择或新增商户；具名商户内才显示记录商品，相机只携带该店，不读取旧任务或旧店缓存兜底。历史无店商品仍可编辑并补店，但不能继续创建新的无归属商品。开发者工具实际交互确认取消返回、对比长按、对比转管理和普通编辑均无状态残留；没有用界面测试修改真实数据。

商品复看页保持一个清楚的日期和商户范围。搜索、状态、分页、AI整理回包、管理和对比状态分别守住当前范围；进入管理会结束对比并清空持久选择，对比中的长按不触发删除。录入入口不与比较/管理同时出现，避免现场误操作。

导出表不采用无限自动列宽。文字列按内容和字号在最小/最大值之间变化，默认11列整体受约163个Excel字符宽的预算约束，优先让备注、业务文字、货号和条码换行；异常大的金额、数量或体积只在自身单元格局部缩放，不能把其他商户页一起压成小字。字段行按标签换行动态增高，默认32pt下限；默认短正文无图可收紧至36pt，较大字体和长备注按实际换行增高。保存过的公司模板宽度或显式行高继续保留。

图片按实际宽高比和每行一/两列网格决定行高；方图与竖图以112px清晰上限排版，超宽图降低行高，双图并排、六图2×3，均不裁切、不越出商品行。最终同参考数据的10店38行44图原生Excel和渲染对照确认主表比例、辅助列和留白更接近参考文件。超过Excel单行409pt上限的合法长备注自动拆成同列连续行，分享和打印仍能读完；数量、金额和TOTAL只保留在商品主行，避免重复计算。含续行的工作表不启用自动筛选，避免排序后备注离开对应商品；没有续行的普通表继续提供筛选。

最终229项TS、253项CJS和完整构建检查通过，后端027真实容器导出通过。交叉复核未发现剩余P1/P2。手机扫码、相机、软键盘、弱网和微信分享仍是独立真机验收项。

2026-10-16，面向义乌现场选品、办公室复看与商品表交付。外部产品和设计参考用于理解交互，具体选择以用户的简洁偏好及本项目工作流为准。

本轮参考了 [Airtable 的数字与评分字段](https://support.airtable.com/docs/rating-field)、[Sortly 的自定义字段](https://www.sortly.com/features/custom-fields/) 和 [Nielsen Norman Group 的日期输入分析](https://www.nngroup.com/articles/date-input/)。Airtable将评分用于排序或质量判断，Sortly允许记录物品的特有信息，日期输入分析讨论了近期日期选择与远期跳转的不同负担。这些是参考依据，不是对本项目用户研究的替代。

目前落实了“留住款式 → 写下判断 → 复看比较 → 导出”的轻量流程：商品图上的爱心直接保存收藏，“我的”集中进入收藏；评分和评价帮助记住喜欢或犹豫的原因，在列表、对比和Excel中复用。个人评价不由AI代写，修改评价不撤销采购事实的确认。

日期采用可滑动、可点击的日期条，有数据的日子带点，并提供前后一天与日历跳转。任务按任务日期浏览；商品回顾按中国时间首次保存日浏览，后续编辑不挪动记录日。去掉选品顶部模式标签，日历图标和“我的 → 历史记录”承担回顾入口。

继续验证的方向是客户或系列的收藏分组、简短标签、供应商快速回访、样品与待问事项跟进。现有备注和评价已能记录这些内容；增加独立管理结构前，需要看真实选品量、复看频次和实际漏问问题，避免把现场页面塞满低频功能。本轮尚未实现收藏文件夹、标签体系、自动提醒或供应商CRM。
