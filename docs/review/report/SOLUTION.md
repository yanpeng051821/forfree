## 1 产品与取舍

一句话：采购人员自己在各商家记录商品，之后查找、补充、比较，把记录整理成参考样式的 Excel。

主线：**选择商户 → 拍照/录入 → 保存 → 从商品列表复看补充 → 按日期和商户导出商品表。**

| 类别 | 正式决定 |
|---|---|
| 保留 | 商户、商品两个 tab，右上角设置入口；系统相机/相册；最多六张照片；个人收藏、评分、备注；两件比较；现有公司模板、内部记录与回收站 |
| 必须修 | 草稿恢复与安全清理、容器大文件分段、本地文件缓存、编辑返回位置、资料核对撤销、导出文件复用、范围说明、Excel 派生公式 |
| 本期小优化 | 有文字的保存按钮；核心字段前置、包装折叠；商品页连续日期范围；紧凑/大图切换；导出前数量、缺项、模板原文可见 |
| 本期不做 | 独立整理队列/逐字段 AI 来源系统、任意搜索结果或所选商品导出、独立商户档案/自动合并、照片裁剪旋转、先拍多件的离线上传队列 |
| 明确排除 | 下单、采购单、批次、计入/取消/后补、商户确认、发送状态、客户 CRM/报价回选、收货、付款对账、团队共享、柜容预算、独立 Web 工作台 |

“本期不做”不是默认下一期承诺，有实际使用反馈再评估。隐藏采购页、旧导出文件和原始数据不删除、不接入主流程。数量、付款文字或唛头出现在参考表里，只说明需要保留资料，不推导出交易流程。

## 3 录入字段与最小保存条件

新品必须有合法现有 `projectId` 和明确当前商户。在名称、货号、照片、现场描述中至少有一项商品信息；只有自动带入商户、默认币种或偏好不允许保存空记录。

名称可后补：有货号而没名称，保存时以货号作为名称；只有照片/描述而没名称，存“未命名商品”。不依赖 AI 开关才能保存，不改变服务端名称非空约束。价格、数量、MOQ、体积、条码与联系方式均非必填。

| 显示位置 / 顺序 | 真实字段 | 规则 |
|---|---|---|
| 顶部上下文 | `supplier` | 当前店始终可见，新品录入时锁定；换店回商户入口 |
| 照片 | `photos` | 最多六张，第一张封面；系统相机为主，相册补图；不改变原图 |
| 现场描述 | `description` | 原话保留，可整理；不默认混进商品表备注列 |
| 核心 | `name` → `unitPrice` + `currency` → `sku` → `colors` | 价格与货号并排；币种始终可见，不强制默认元/件适用于所有商品 |
| 核心末尾 | `exportRemarks` | 文案“商品说明 / 表格备注”；默认商品表会带出，与个人内部备注区分 |
| 规格与包装折叠 | `cartonQty`、`moq`；`cartons`、`quantity`；`cartonDimensions`、`cartonCbm`、`barcode`；`material`、`dimensions`、`weightG`、`leadTimeDays`、`tradeTerms` | 每箱数与起订量分开；数量文案“记录数量（件）”，不是下单数量；未知留空 |
| 扩展字段折叠 | `custom` | 现有模板最多八项自定义列；隐藏模板列不删除已存值 |
| 商户资料折叠 | `supplierContact` | 名称/摊位沿用顶部身份；联系方式选填，不反复录 |
| 个人评价折叠 | `notes`、`evaluation`、`rating` | 个人待问事项/评价，不默认出现在商品表 |
| 辅助操作 | `favorite`、`confirmed` | 收藏与“资料已核对”独立，均不代表选购决定 |

规格与包装首次默认收起；用户手动展开/收起后在本账号本机记住，记录下一件继续沿用。其他低频区首次收起，填过的区展示摘要；草稿恢复与字段报错时临时展开对应区，不覆盖用户偏好。不因为 AI 补一个低频字段自动撑开全部表单。

底栏：新品“保存返回”（次要）/“保存并继续”（主要）；已有商品“保存修改”（主要）/“返回”（次要，保留草稿）。新增成功后继续仅携带商户/联系方式、个人默认币种和展开偏好，不携带上一件价格、箱数、货号或照片。编辑历史商品时“记录新品”放到次要操作，不让两个保存圆图标承担不同含义。

**云端确认保存成功才允许清空并进入新品。** 本机写入只提示“草稿已保存”；请求回执不明提示“保存结果待确认”，不提前展示云端成功。

## 4 AI 与人工核对：只有一个简单标记

保留 `confirmed` 的资料核对语义和历史值，不迁移成采购状态或完整度。系统缺项由实际字段计算；不新增来源表、逐字段 `accepted` 状态、AI 待确认专用筛选或审批队列。

“AI 整理”可填明确图文中的空字段，包括把“未命名商品”补成名称；人工已有值不覆盖，估算值不进入正式字段。前台提示本次补了哪些字段，冲突值保留人工输入；后台用已有 `organizeState` 显示“整理中/已整理，待核对/整理失败”。不能在没有来源数据时声称某个值“来自标签第几行”。

两条保守规则前后台一致：

- 商户身份和联系方式只来自商户入口/人工，不由商品照片或描述自动换店。
- 币种保持用户当前选择；提取价格明确使用其他币种时，不自动填入该价格，提示用户核对币种后再整理。没有明确币种时按当前已显示币种处理，不按外观猜，也不把人工选择默认为系统可覆盖值。

保存后后台整理开关沿用现有能力：首次默认开，按账号记住选择；能力未确认、关闭或不可用时正常手填保存。整理失败不使已保存商品失败。结果到达前商品版本有变，则不覆盖；重新整理只能再次补空。

撤销核对采用固定字段名单，不依赖当前模板是否显示：

- 值实际变化才撤销：`name, sku, supplier, supplierContact, colors, material, dimensions, weightG, unitPrice, currency, moq, cartonQty, cartons, quantity, barcode, exportRemarks, custom, cartonDimensions, cartonCbm, leadTimeDays, tradeTerms`；新增或删除照片也撤销。
- 不撤销：`description, notes, evaluation, rating, favorite`，仅调整照片顺序/封面、折叠状态和公司格式。
- AI 只改内部备注或完全没补到值时，不无条件撤销；事实字段补空才撤销。币种不一致的结果不是已补值。
- 撤销时展示“资料有改动，请重新核对”；人工可在有空字段时标“资料已核对”，含义是检查过已记录的信息，不承诺资料完整。

## 5 草稿、返回与范围

### 草稿默认恢复，不静默丢弃

从卡片打开已有商品时，按账号 + `projectId` + 商品 ID 查草稿；有有效未保存修改则默认继续，明显显示“已恢复本机未保存修改”，并提供“查看已保存版本”。显式草稿入口同样恢复。

查看已保存版本是只读，不写同一草稿、不自动撤销/删除草稿；要改该版本必须先选择继续草稿，或明确确认放弃该商品草稿。云端版本不同则展示现有冲突核对，不静默覆盖。原商品在回收站时先恢复；损坏草稿可由本人确认放弃。

只删除**本次成功保存所对应的草稿快照**：清理前再次比对草稿标识/内容，保留期间产生的新修改及其他商品草稿。清理照片前核对所有草稿、编辑和上传引用；云端照片已确认上传后才释放对应本机原图。失败、切后台和会话到期保留输入；幂等重试先取回执，不创建重复商品。

### 返回列表保留上下文

编辑前保存账号、日期范围、商户、搜索、资料状态、视图模式、已加载页面和滚动锚点。相同上下文返回只查询/更新变更记录；未保存返回也保留位置。

修改导致当前行不再符合筛选，移除该行并用邻近商品作为锚点；本地匹配必须与服务端搜索字段一致，不能拿旧的前端简化搜索规则判断。列表失效或匹配不确定时重新查询已加载范围并恢复锚点，不回到第一页。账号/日期/商户明确改变时才换范围；下拉刷新是主动全刷新。

### 日期范围与筛选

商户默认今天；商品初次进入默认今天全部商户，从商户跳转则保留该店/日期。同账号返回保留最近上下文。商品页增加“单日 / 日期范围”轻量选择，起止日期含首尾，结束不晚于今天；复用现有范围接口及能力检查，不新增批次或日期字段。

记录日由 `createdAt` 转北京时间得到，不用 `project.date/taskDate/updatedAt`。从历史日期录新品仍按首次云端保存当天归属；本机草稿日期不冒称正式记录日。日期改变清除无关的比较选择；扩范围不建立长期候选组。

列表保留 `all/pending/confirmed/missingPrice` 四种资料筛选，搜索在当前日期/商户范围内。先保留大图默认，用户可切紧凑，账号本机记住。不给 MOQ、箱数等所有可选字段做“必补任务”。

## 6 导出规则：范围明确，仍是商品记录

主入口在商品页，名称“导出 Excel”；默认商品表、全部已保存有效记录、带每件全部照片。支持单日或连续日期范围 × 全部商户或一个商户，另可显式选“仅已核对”。旧收藏/单 project 入口兼容，不与主日期范围混用。

本期**不增加 `q/status/ids` 导出协议**：

- 列表状态 `confirmed` 可以映射为 `scope=confirmed`。
- 搜索、待核对、缺价格只筛列表，不自动筛导出。进入导出页固定提示“搜索 / 缺项筛选不带入 Excel；本次按以下日期、商户与核对范围导出”，实际商品数重新查，不沿用列表匹配数。
- 按钮不用“导出当前筛选/导出所选”等未实现含义；零件不生成，超限提示缩小日期/商户范围。

同一精确 `supplier` 跨日一个 sheet；同货号的不同记录逐条保留，不去重、不相加、不仅取最新。无商户的旧记录可导出“未填写商户”sheet。草稿、回收站排除；“取消/后补”等备注只是文字，不自动排除。

预览显示真实导出数量、商户数、价格/数量/体积缺项，商品行前几条只是样例预览，不假称全部已看。当前接口不足的缺项计数补进现有导出预览元信息，不引入完整度实体。列预览可横向滚动；付款条款、唛头和包装要求按现有模板原文折叠显示，本期不加“本次付款方式”等覆盖字段。

### 参考列精确映射

新默认带图商品表保留下列 A:K 十一个基础列；隐藏的商户/核对/币种列按现有模板设置启用，不重置用户列名、顺序与格式。无图模式仅省略图片列，后续列位置随之变化，不写死字母。

| 默认列 | 参考列名 | 实际来源 / 规则 |
|---|---|---|
| A | REF. | `sku`，字符串 |
| B | CTNS（箱数） | `cartons`，未知空白，0 有效 |
| C | PCS/ CTN | `cartonQty` → 模板 key `pcsPerCarton`，已知须为正整数 |
| D | QUANTITY(数量） | `quantity` 手填优先含 0；未手填才用 B×C |
| E | PRICE (价格RMB) | `unitPrice`，实际币种为 `currency` |
| F | AMOUNT (RMB总金额) | D×E，乘数未知空白 |
| G | 备注 | 名称（与货号相同不重复）+颜色+材质+商品尺寸+外箱尺寸+`exportRemarks` |
| H | 图片 | 该记录所有已保存照片，按顺序摆入同一商品主行 |
| I | 体积 | `cartonCbm`，单箱 m³，不从外观或含糊单位推算 |
| J | 总体积(m³) | B×I，乘数未知空白 |

商品表不默认带出 `description/notes/evaluation/rating/favorite/supplierContact`；现有内部记录模式仍可包含这些资料，放到次要选项，不删除历史字段。

新默认标题统一“商品资料表 / PRODUCT RECORD”；默认可选 `decision` 列名改“资料核对”（仍不默认启用），不是“处理决定”。已保存模板标题、列名包括“采购记录”全部保留，不自动改写。模板为新默认还是已保存须按已有版本规则判断，不能按文字相同擅自覆盖。

### 数值与公式

数值空白是未知，不自动填 0；显式 0 允许价格、箱数、记录数量与体积，`cartonQty=0` 仍无效，MOQ 独立不参与数量计算。手填数量与箱数×每箱数不同，只提示，保留手填并照常导出。

本期给派生值写 Excel 公式与相同缓存值：手填 `quantity` 保留数值；未手填的数量、金额、总体积写以实际列位置组装的公式。示例（仅默认 A:K 第七行）：`IF(COUNT(B7,C7)=2,B7*C7,"")`、`IF(COUNT(D7,E7)=2,D7*E7,"")`、`IF(COUNT(B7,I7)=2,B7*I7,"")`。未知乘数缓存值为空；0 参与计算。隐藏/重排/无图/扩展列下按 key 定位，不引用不存在列。

TOTAL 保留现有带 COUNT 完整性判断的 SUM 公式，长备注续行只引用商品主行；对应有未知数的整项完整合计留空，不以已知部分冒称全总计。补商品行公式后，TOTAL 缓存值须读取主行公式的有效缓存结果，不能继续只按 `cell.value` 是否 number 判断。不同币种分开 TOTAL，外币价格/金额显示币种，列名不得冒称人民币，不换算也不混加。每箱数、单价和单箱体积不求和；不新增运费或下单口径。

格式沿用现有表头、字体、动态有界列宽、多图网格与长备注续行；有续行时不启用会拆散记录的排序筛选。文本以文字写入，`=...`、前导零不解释成公式。实际模板最终打印/打开验收，不以静态五列缩略图代替十一列 Excel。

### 生成文件复用

成功生成后显示“打开文件 / 分享文件”，同页面返回不自动清空。复用键包含账号、日期/商户范围、scope、audience、带图开关、模板版本；变更这些条件或确认相关记录已改，旧文件不再冒充当前预览。

本期不做后台自动同步：已生成文件是当时快照，标出生成时间，用户可明确“重新生成”取最新。文件还在、账号一致时再次打开/分享不重生成；文件丢失或损坏则提示重新生成。取消分享不删除文件；迟到结果不能写进已改变的范围。

## 7 三项可靠性方案

### R1 草稿保护

按第 5 节修复，不换数据模型，不新建云草稿同步。修改前本机复现 `../verify-prod/repro-draft-loss.js`：卡片重开未读草稿，后续保存删草稿和本机照片。第一批已修改相关逻辑并增加自动化回归；历史复现不是新代码验收记录，真机仍需补验。

### R2 容器安全分段：确定一条路径

继续鉴权的 `callContainer`，不启用公网下载兜底、不先换云存储架构。原 `/api/jobs/:jobId/file` 默认旧协议保留；新增显式 `protocol=2` 及能力字段 `exportFileV2`，新客户端只在服务端声明后使用 v2。旧客户端小文件路径不回归；旧服务端只允许新客户端走已有验证过的小文件路径，大文件明确提示服务不兼容，不能假下载成功。

v2 二进制块最大 **640 KiB（655,360 bytes）**，元信息包含协议号、总字节数、chunkSize、块数、文件 SHA-256。块长/offset/owner/job 逐项校验。实现阶段测真实通道响应表示和封装；传输响应保守预算 **≤900 KiB**，若不满足则进一步减块，不改单条产品路线。当前二进制请求是 `arraybuffer`，不把它误说成天然 base64；若通道出现 base64 才计其 4/3 开销。

块写入临时文件并记录已完成偏移，重试复用同 job；以最后已验证块为检查点，避免重复追加；全部下载后校验 size 和 SHA-256，通过才成为可打开/分享的 `.xlsx`。哈希是文件完整性校验，不取代鉴权。GET 限流/暂时断网按 0.5/1/2/4 秒加抖动退避，取消/账号变化立即停止；过期 job 明示重新生成。写商品请求仍按幂等回执重试。

Excel 嵌图只对导出副本做方向归正、等比缩至长边不超过 1024px、JPEG 质量初值 80，不改变采集原图；文字标签模糊时调整压缩参数，以文件体积和可辨认程度实测验收。不为了小文件只留封面，默认全部照片保留。

现有最多 500 件、输入图片 40 MiB、成品 80 MiB 的服务端硬上限暂保留；不得宣传这些边界在手机均已通过。页面预检查空间，过大明确缩范围/无图选项；不让半文件显示成功。

### R3 本地文件引用保护

照片缓存按账号 + photo ID + 原图/缩略图规格索引复用；导出按 job 和范围索引。可再取缓存预算 **60 MiB**，未被使用的导出最长保留 **7 天**；这是本期内部清理参数，不是平台配额声明。写入前/文件释放后触发 LRU，不靠每次浏览另写随机文件。

所有草稿、新照片、待上传/回执不明、编辑器引用、比较/预览、下载中和打开/分享中的文件受保护。预算不足先删除索引确认可再取的文件；受保护数据仍超预算则提示释放空间/缩小导出，不静默删记录。

失败导出只清理本次明确的无引用临时块；重试检查点在 job 有效时保留。无法证明归属或引用的旧文件先不删，不能递归清空 `USER_DATA_PATH`。清理 API 报错不影响草稿写入结果表达。

实施阶段再核验平台官方限制与真机行为。本轮尝试读取当前官方页面未取得正文；640/900 KiB 与 60 MiB/7 天是保守方案参数，不是假称已重新核实的最新平台上限。
