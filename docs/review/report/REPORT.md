## 1 目标与结论

采购人员自己到商家记录商品的照片、价格、货号、包装，自己查找、补充与比较，最终得到参考样式 Excel。

主线：选商户 → 记录商品 → 保存 → 在商品列表复看补充 → 按日期/商户导出商品表。

最终为商户 / 商品两个 tab，右上角进入设置，复用原 `pages/me/index` 普通页面和既有数据。**不做下单、采购单、批次、计入/取消/后补、商户确认、发送状态、客户 CRM/报价回选、收货、付款对账、团队共享、柜容预算或独立 Web 工作台。**

参考表里的付款、唛头、数量和取消备注是需要忠实保留的资料，不能推导出完整业务系统。旧研究和旧 handoff 里扩大范围的建议已撤回，不是待开发需求。

## 2 用户场景对应的最小设计

### 现场记录

当前店始终可见。照片和现场描述先记录，名称、单价/币种、货号、颜色及表格备注在前；数量、每箱数、箱规、体积、MOQ 等折叠后补。记录数量不是下单数量，MOQ 不参与数量计算。

新品有当前商户和至少一项商品信息即可：名称可用货号或“未命名商品”后补，不让 AI 开关成为保存前提。空商户/只有默认值不能产生空商品。缺价格、数量、条码等不拦保存和导出。

新品“保存返回 / 保存并继续”，已有商品“保存修改 / 返回”，按钮带文字和主次。云端成功才清空继续新品，不承诺未经可靠持久队列支持的保存即走。规格展开偏好本机记住。

系统相机/相册保留，不开发页内相机、录音或多件离线队列。封面/多图沿用；裁剪旋转以后有实际反馈再做。

### 自己补资料

从商品列表点开现有编辑页补充，不新增“整理队列”、候选建议采纳或保存下一件历史商品。返回保留范围、分页、滚动锚点；这种复用比另建队列更符合当前简洁场景。

`confirmed` 是人工检查现有资料，不是齐全、买不买或商户确认。固定事实字段实际改变才撤销；内部备注、评分、收藏与封面排序保留。系统按字段算缺项，不新增状态模型。AI 只填明确空值，人工优先，不自动换商户/币种；无来源数据不画标签出处。

两件比较及已有差异筛选保留，回归模式互斥和退出恢复；不建候选组，不按不同币种、不同规格自动推荐更优。

### 商户与范围

复用 `Project` 和 `supplier` 文字；名称/摊位沿用一个输入、市场/位置及联系方式选填，不新增 `booth`、独立商户 ID 或迁移。旧同名合并是已知限制；不自动改历史记录。

单日或连续日期范围含首尾，记录日由 `createdAt` 转北京时间得到，修改不改所属日。主导出日期/商户全部有效记录；已核对可显式筛选。搜索、待核对、缺价格只筛列表，本期不加 q/status/ids 导出协议。

## 3 Excel 的真正要求

新默认带图商品表保留参考 A:K：货号、箱数、每箱数量、数量、价格、金额、备注、图片、单箱体积、总体积、条码。映射表与公式在 `SOLUTION.md` 第 6 节，不能按设计缩略图的五列落地。

同精确商户文字跨日一个 sheet；同货号不同记录不去重、不相加、不只取最新。草稿/回收站排除，取消备注不自动排除。未知数留空、显式 0 有效，每箱数量已知为正整数；手填数量优先，未填才箱数×每箱数量，缺乘数相关完整合计留空。不同币种分开 TOTAL，不加运费、付款或采购决定计算。

派生数量、金额、总体积计划写公式及缓存值，手填数量保持数值；列重排、无图、自定义列按字段 key 定位。当前代码只有 TOTAL 公式，不能称商品行已完成。加入公式后 TOTAL 缓存值也必须按商品主行的有效结果计算，而不是只认 `cell.value` 为 number。

保持已保存模板的标题、列名、字体、宽度、表头和表尾原文；仅新默认改“商品资料表 / PRODUCT RECORD”。商品表默认不带个人描述、评价和联系方式，内部记录保留为次要模式。付款/唛头只预览并原文导出，不加本次业务状态。

已有多图网格、有界动态宽度、长备注续行保留；续行不重复计数，有续行的表不启用会拆散记录的排序筛选。真实 XLSX 打开与打印为准，不以示意截图当验收。

### 参考样本及历史口径

原 Excel 在 `forfree/docs/`，被 Git 忽略但本机存在。本轮之前已只读检查：20 worksheet、16 drawing、90 media，这是部件数，不等于 20 商户/90 商品图片。历史去重参考式输出：10 商户、38 商品、44 图、10 TOTAL；全记录样本 96 箱、24,876 件、79,260、7.320 m³。

这些是特定样本的历史验收，不是所有文件的固定数值。原表合计和剔除取消/计入后补/加运费的旧采购假设口径不同；旧 90 箱/70,491.60 不作为本期正确商品表硬指标。

真实参考表及图片只留本机；云端验收用同构合成数据，不上传真实商户、商品或联系方式。

## 4 技术路线与实施顺序

四批：①两 tab / 设置与草稿安全（本地已开始）；②容器兼容分段及缓存；③字段/核对/返回/日期范围；④Excel 与文件闭环。详见 `SOLUTION.md` 第 7–8 节与 `../HANDOFF-TODO.md`。

容器 v2 最大 640 KiB 原始二进制块，实际响应保守预算 ≤900 KiB；协议能力协商、偏移检查、文件 size/SHA-256 校验及断点重试。不单边改旧元信息；不假设 arraybuffer 天然经过 base64。新旧后台先兼容，发布授权另行确认。

可再取本机缓存预算 60 MiB、导出最长七天，只清明确索引且无引用的文件；草稿、上传、编辑、比较、预览、下载、打开/分享均保护。超预算提示，不递归清空 `USER_DATA_PATH`。压缩只作用于 Excel 副本，保留全部已保存图。

视图只传必要数据、局部更新；连续翻页不挤掉保存请求，图片/列表/写必要分组退避。当前 PG、队列多实例、虚拟化等规模观察保留在历史问题登记，不同时扩成第一期架构重建。

这些技术值是本期内部保守参数，不是宣称已重新核验最新平台限制。本轮官方页面请求未取到正文，实施时仍需核验并测实际通道；没有因此留下“容器还是公网”的架构选择待决。
