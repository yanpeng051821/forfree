# 第四轮来源复核

日期：2026-10-24。原研究产物保留为证据，不代表每条结论通过核验。范围以负责人本轮澄清为准：个人商品记录、整理、商品 Excel；不做下单或批次系统。当前规格见 `REPORT.md`、`INDUSTRY.md` 和 `design.json` v1.2。

## 方法与结果

沿用 tclaude 的 DeepSeek 搜索接口，以五组通用查询补检唛头、岗位、地方标准、付款和条码；八个原网页请求中七个取得可读正文，一个只有空标题。没有将真实工作簿名称、商户、摊位、代号、照片或联系方式发到网络。新增证据正文中的联系方式已遮蔽。

DeepSeek 摘要用于找来源，不能代替原文。来源记录见 `../revise-r4/evidence/searches.json`、`pages.json`；逐条结论处理见 `../revise-r4/claim-audit.json`。未逐条复核的历史来源明确标为“历史存档/未独立复核”，不沿用原研究的 high 标签作为保证。

本轮有三层依据：

| 层级 | 能说明什么 | 不能说明什么 |
|---|---|---|
| 官方标准/GS1 原文 | 文件当时的规定、示例或标识规则 | 公司流程、普及率、所有字段必填、现行有效性 |
| 公司原网页 | 这家公司的规则或经验 | 全行业一致、痛点排序、本公司必须照做 |
| 本机代码/脱敏原型/样本 | 现状机制、具体样本结构、给定口径结果 | 正式员工习惯、已签认金额、真实手机体验 |

## 重要纠正

| 历史结论 | 当前处理 | 依据或原因 |
|---|---|---|
| 入仓号=客户码=会员号，全行业同义 | 限定到具体公司；不据此新增实体 | YPTC 当前正文明确无统一通用入仓号；DJcargo 和 Angkat 规则不同 |
| 样本代号就是客户身份 | 待最终使用者确认，不建 CRM | 公开公司规则不能解释私有样本 |
| 文件名与保存路径不同，证明同时做两批、复制上一批 | 只作模板复用的可能线索 | 元数据不能证明同时工作或复制动作 |
| 6.4 m³ 证明拼箱、不是整柜 | 撤回运输方式推断 | 单个样本体积不足以确认运输安排 |
| 多数公司采购/业务/仓库分工固定 | 改为岗位实例，不断言比例 | 无代表性样本；职位职责互相重叠 |
| 纸+微信+Excel 是主流 | 仅保留工具使用实例 | 企业宣传、投诉或招聘不能估普及率 |
| 五大痛点按频率排序 | 撤回排序，保留具体风险例子 | 未有可比较的统计总体、样本量和频率 |
| 付款30更可能30天／更可能30% | 两种判断均撤回，存原文 | 历史报道、课件和模板解释不相同 |
| PI标题证明借了客户报价模板 | 仅列未知模板来源 | 标题不能证明来源、法律性质或接收对象 |
| 69开头13位即可、可生成零售条码 | 不生成；按确认的码类型校验 | GS1 GTIN 与其他编码分开；格式通过不等于授权或归属验证 |
| 同码出现两行即重复错误 | 本期可选字符串列，不做复杂查重流程 | 商品记录、商品标识和外箱标识粒度不同 |
| 体积完整才准导出 | 缺项披露但允许导出商品记录 | 未知是合法记录，不是采购确认 |
| 分享回调自动已发/商户确认 | 不建发送/确认状态 | 文件分享不是下单流程 |
| 参考表含采购字段，所以必须建采购单 | 撤回；按日期/商户组织商品表 | 用户再次明确不做下单；docs 也不增加采购步骤 |
| 768KiB或900KiB原始分段小于1MB | 实测此通道表示，按实际响应字节数控制 | 若经过base64，768KiB已达1MiB，尚未加封装；不能忽略编码开销 |
| 服务端直接改小分段，之后更新客户端 | 双协议能力协商、旧客户端兼容 | 旧客户端检查4MiB固定值，单边改会回归 |

## 未通过与待核验

- `ywsst.net/shipping/25.html` 本轮抓取为空，标失败；不把“请求结束”记为来源核实。旧研究中“商翔/硕程”的公司名称有不一致，不在当前报告引用它。
- 招聘、论坛、宣传稿、软件上架时间及使用数字不重新升级为高置信度；当前报告不依赖其普及率或时间承诺。
- 2022 年相关团体标准材料若标征求意见稿，只能证明草案内容；不写成已施行标准。
- 尚未对条码管理办法的最新法条与效力做完整法律核验；当前建议不依赖该法律推断，而采用“不替用户生成零售编码”的保守工程边界。
- 标准、公司规则和平台文档会变化；实施前应再核验相关原文，平台硬限制尤其要测真实通道。
